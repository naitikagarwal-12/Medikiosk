# Deployment

MediKiosk is a monorepo with three deployable parts:

| Part | Path | Platform | Runtime |
| --- | --- | --- | --- |
| Frontend (React + Vite) | repo root | Vercel | Static SPA |
| Backend API (Express) | `backend/` | Render | Node 22 |
| Bhashini Bridge (Flask) | `backend/bhashini/` | Render | Python 3.11 |

Config lives in `vercel.json` (frontend) and `render.yaml` (Render Blueprint for both backend services). No secrets are stored in the repo — every sensitive value is entered in the provider dashboard.

---

## 1. Backend + Bhashini on Render

1. Push this repo to GitHub.
2. In Render, create a new **Blueprint** and select the repository. Render reads `render.yaml` and creates both web services (`medikiosk-backend`, `medikiosk-bhashini`).
3. Render will prompt for every variable marked `sync: false`. Supply them (see tables below). `JWT_SECRET` and `JWT_REFRESH_SECRET` are auto-generated by Render.
4. Deploy. The backend health check is `GET /health`.

### `medikiosk-backend` environment variables

| Key | Value | Notes |
| --- | --- | --- |
| `MONGODB_URI` | your MongoDB Atlas connection string | manual — add Render's IPs (or `0.0.0.0/0`) to the Atlas allowlist |
| `CORS_ORIGIN` | your Vercel frontend URL | manual — e.g. `https://medikiosk.vercel.app` |
| `ABHA_API_KEY` / `ABHA_API_SECRET` | ABHA credentials | manual (optional until ABHA is enabled) |
| `GROQ_API_KEY` | your Groq key | manual |
| `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | mail credentials | manual (optional; enables notifications) |

Non-secret defaults (`NODE_ENV`, `JWT_EXPIRES_IN`, rate limits, `GROQ_API_URL`, `ABHA_API_URL`, `OCR_PROVIDER`, `UPLOAD_DIR`, `MAX_FILE_SIZE`, `SMTP_HOST`, `SMTP_PORT`) are set in `render.yaml`. `PORT` is injected by Render automatically.

### `medikiosk-bhashini` environment variables

| Key | Value | Notes |
| --- | --- | --- |
| `CORS_ORIGIN` | your Vercel frontend URL | manual — comma-separated list also accepted |
| `BHASHINI_API_KEY` | Bhashini ULCA userID | manual |
| `BHASHINI_UDYAT_KEY` | Bhashini ULCA API key | manual |
| `BHASHINI_INFERENCE_KEY` | Bhashini inference key | manual |
| `GROQ_API_KEY` | your Groq key | manual (fallback path) |

## 2. Frontend on Vercel

1. In Vercel, **Add New → Project** and import the same GitHub repository.
2. Root Directory: leave as the repository root (the frontend lives there). `vercel.json` sets the build command (`npm run build`), output (`dist`), and the SPA rewrite for client-side routing.
3. Add the environment variables below, then deploy.

| Key | Value | Notes |
| --- | --- | --- |
| `VITE_API_URL` | Render backend URL | e.g. `https://medikiosk-backend.onrender.com` |
| `VITE_BHASHINI_URL` | Render Bhashini URL | e.g. `https://medikiosk-bhashini.onrender.com` |
| `VITE_GROQ_API_KEY` | your Groq key | used by the sign-language tokenizer |

> Vite inlines `VITE_*` variables at build time. After changing any of them, redeploy the frontend.

---

## 3. Wiring the three services together

After the first deploy, cross-link the URLs (each side must know the other's public origin):

- Vercel → `VITE_API_URL` = backend URL, `VITE_BHASHINI_URL` = Bhashini URL.
- Render backend → `CORS_ORIGIN` = frontend URL.
- Render Bhashini → `CORS_ORIGIN` = frontend URL.

Then redeploy/restart the affected services so the new values take effect.

---

## Notes

- **Ephemeral disk on Render:** the backend writes uploads to `UPLOAD_DIR` (`./uploads`), which is wiped on every deploy/restart. Attach Render Disk or switch to object storage (e.g. S3) if uploads must persist.
- **Free plans sleep:** Render free-tier services spin down when idle; the first request after a pause is slow.
- **Rotating keys:** any API key that was previously committed to an example file should be treated as compromised and rotated before going live.
